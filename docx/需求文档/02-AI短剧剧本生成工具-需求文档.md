# AI短剧剧本生成工具 - 需求文档 v1.0

## 1. 项目概述

### 1.1 项目背景
短剧创作需要完整的剧本体系（角色、大纲、分集剧本），但直接使用AI平台存在上下文丢失问题。本工具通过智能提示词管理，让用户可以在任何AI平台（ChatGPT/Claude/文心一言等）高效生成高质量短剧剧本。

### 1.2 核心价值
- **无需API对接**：用户手动复制提示词到任意AI平台
- **上下文自包含**：每个提示词包含完整必要背景，无惧新对话
- **推荐路径 + 自由模式**：既有向导流程，也支持自由跳转
- **专业化管理**：版本控制、一致性检查、多格式导出

### 1.3 目标用户
- 短剧编剧（新手/专业）
- 内容创作者
- 自媒体从业者
- 剧本爱好者

## 2. 功能需求

### 2.1 核心功能模块

#### 2.1.1 项目管理
**功能点：**
- 创建/编辑/删除项目
- 项目信息：名称、类型（霸道总裁/悬疑推理/甜宠/复仇/穿越等）、集数、每集时长、目标受众
- 项目状态跟踪：进度百分比、当前阶段（设定/大纲/剧本/优化）
- 多项目并行管理

**交互：**
- 项目列表卡片视图
- 快速搜索/筛选（按类型、状态、创建时间）

#### 2.1.2 推荐工作流（向导模式）
**标准路径：**
```
Step 1: 基础设定 → Step 2: 角色设计 → Step 3: 剧情大纲 
→ Step 4: 分集梗概 → Step 5: 详细剧本 → Step 6: 优化润色 
→ Step 7: 导出成品
```

**每个Step的功能：**
1. **基础设定**
   - 填写：类型、集数、时长、核心冲突、情感基调
   - 生成：《项目设定提示词》

2. **角色设计**
   - 自动加载：项目设定上下文
   - 用户输入：主角数量、配角需求、特殊要求
   - 生成：《角色设计提示词》（含项目背景）
   - 保存：AI返回的角色卡（可编辑）

3. **剧情大纲**
   - 自动加载：项目设定 + 角色信息
   - 用户输入：主线条数、节奏要求（快/慢/张弛有度）
   - 生成：《大纲生成提示词》
   - 保存：完整大纲（可分幕/分章）

4. **分集梗概**
   - 自动加载：设定 + 角色 + 大纲
   - 用户选择：生成范围（第1-10集/第11-20集）
   - 生成：《分集梗概提示词》
   - 保存：每集的3-5句核心情节

5. **详细剧本**
   - 自动加载：前置信息 + 目标集数的梗概
   - 分包策略：每次生成3-5集（可配置）
   - 生成：《详细剧本提示词》（含前情提要）
   - 保存：场景描述、对白、动作、情绪标注

6. **优化润色**
   - 选择：特定集数或全部
   - 优化方向：对白打磨/情感深化/节奏调整/冲突强化
   - 生成：《优化提示词》

7. **导出成品**
   - 格式：Markdown / Word / PDF
   - 可选：封面页、角色表、大纲附录

**向导特性：**
- 进度条展示当前位置
- 支持"上一步""下一步""跳过"
- 每步可重复执行（版本覆盖或新建版本）

#### 2.1.3 自由创作模式
**功能点：**
- 不受向导限制，可直接创建任意模块
- 卡片式布局：角色卡、大纲卡、剧本卡独立管理
- 自由关联：可手动选择哪些内容作为上下文
- 自定义提示词：基于模板修改或完全自定义

**适用场景：**
- 有经验的编剧，只需部分辅助
- 非标准流程（如先有剧本片段，再补角色）
- 快速实验/灵感记录

#### 2.1.4 智能提示词生成器（核心引擎）

**输入：**
- 当前任务类型（角色设计/大纲/剧本等）
- 用户填写的表单数据
- 自动加载的历史上下文
- 用户自定义要求

**处理逻辑：**
```
1. 从模板库加载基础模板
2. 注入项目基础信息（类型、集数、调性）
3. 注入必要上下文（角色卡/大纲/前情提要）
4. 上下文压缩（摘要化 + 结构化）
5. 添加输出格式约束
6. 添加一致性要求（称谓、时间线、人设）
7. 组装为完整提示词
```

**输出：**
- 格式化的提示词文本
- 预估字符数/Token数
- 适配平台建议（ChatGPT/Claude/文心等）

**上下文压缩策略：**
- **角色信息**：只保留姓名、核心性格、关键关系、主要目标
- **大纲信息**：转为"开端-发展-高潮-结局"的结构化描述
- **前情提要**：最近3集的核心事件 + 情感变化
- **一致性约束**：关键事实清单（如"男主不知道女主真实身份"）

#### 2.1.5 上下文管理器

**功能点：**
- **上下文可视化**：当前提示词将包含哪些历史信息
- **手动调整**：勾选/取消勾选特定模块（如"不包含配角信息"）
- **压缩等级**：极简/标准/详细（影响上下文长度）
- **平台适配**：
  - ChatGPT（建议≤8000字）
  - Claude（建议≤20000字）
  - 文心一言（建议≤4000字）
  - 自定义限制

**分包策略：**
- 当任务过大时，自动拆分为多个子任务
- 每个子任务提示词独立、自包含
- 提供"衔接提示语"：告诉AI这是系列任务的第N部分

#### 2.1.6 模板库系统

**预设模板类型：**

**A. 项目类型模板**
- 霸道总裁：核心冲突、常见套路、角色原型、情节节点
- 悬疑推理：线索设计、反转技巧、节奏控制
- 甜宠日常：糖点设计、互动模式、甜度曲线
- 复仇爽剧：打脸节奏、反派设计、爽点密度
- 古装穿越：世界观设定、历史融合、金手指
- 职场励志：成长曲线、职场冲突、专业细节

**B. 任务提示词模板**
- 角色设计模板（主角/配角/反派）
- 大纲生成模板（三幕/五幕/序列式）
- 对白打磨模板
- 场景描写模板
- 情感深化模板

**模板管理：**
- 用户可编辑/复制模板
- 可导入/导出自定义模板
- 社区模板分享（可选功能）

#### 2.1.7 内容管理与编辑

**功能点：**
- **角色库**：
  - 角色卡片（头像/姓名/性格/关系图）
  - 支持富文本编辑
  - 关系图谱可视化（可选）

- **大纲管理**：
  - 层级结构：幕 > 章 > 节
  - 拖拽调整顺序
  - 折叠/展开
  - 标注"已完成""待修改"

- **剧本管理**：
  - 按集数/场次组织
  - 双栏对比（旧版本 vs 新版本）
  - 场景标签（日/夜、内/外、地点）
  - 对白高亮、情绪标注

- **通用编辑**：
  - Markdown编辑器（所见即所得）
  - 字数统计（实时）
  - 批注/备忘录
  - 搜索/替换

#### 2.1.8 质量检查与一致性维护

**自动检查项：**
- **人物一致性**：
  - 称谓检查（"李总"/"李浩"/"老李"混用提示）
  - 性格OOC检测（基于角色卡的行为模式）
  
- **时间线一致性**：
  - 季节/时间跨度检查
  - 事件顺序逻辑
  
- **情节逻辑**：
  - 悬念未解决提醒
  - 伏笔未回收提示
  
- **格式规范**：
  - 场景描述格式
  - 对白标点
  - 人名统一

**手动标注：**
- 用户可标记"关键伏笔""重要转折"
- 工具自动追踪是否已处理

#### 2.1.9 版本控制

**功能点：**
- 每次AI生成的内容保存为新版本（可配置为覆盖）
- 版本列表：时间戳、版本号、简要说明
- 版本对比：diff视图
- 回滚：恢复到任意历史版本
- 分支：从某版本创建新分支进行实验

#### 2.1.10 一键复制与导出

**复制功能：**
- "复制提示词"按钮：一键复制到剪贴板
- 格式化：自动添加边界标识（如```提示词```）
- 复制后提示："已复制，可粘贴到AI平台"

**导出功能：**
- **格式**：
  - Markdown（.md）
  - Word（.docx）
  - PDF（.pdf）
  - JSON（项目完整数据）
  
- **导出范围**：
  - 单个模块（如仅角色卡）
  - 完整剧本（包含封面、目录、附录）
  - 全项目打包
  
- **自定义选项**：
  - 是否包含角色表
  - 是否包含大纲
  - 字体/样式（PDF/Word）

## 4. 技术架构（基于RealWeb集成）

> ⚠️ **重要变更**：本工具将作为RealWeb的工具模块集成开发，技术栈已确定。详见《02-AI短剧剧本生成工具-RealWeb集成方案.md》

### 4.1 前端技术栈（已确定）
- **框架**：Vue 3（与RealWeb一致）
- **UI组件**：Element Plus（RealWeb现用）
- **编辑器**：Monaco Editor（代码高亮、Markdown支持）
- **状态管理**：Pinia（Vue 3官方推荐）
- **路由**：Vue Router 4（RealWeb已有）
- **本地存储**：IndexedDB（Dexie.js）
- **HTTP请求**：request.js（RealWeb封装的axios）
- **导出**：
  - Markdown: 原生支持
  - Word: docx.js
  - PDF: jsPDF / html2canvas

### 4.2 数据结构设计（简化版）

```javascript
// 项目结构
Project {
  id: string
  name: string
  type: string  // "霸道总裁" | "悬疑" | "甜宠" 等
  episodeCount: number
  episodeDuration: number  // 分钟
  status: string  // "设定中" | "大纲中" | "剧本中" | "已完成"
  createdAt: timestamp
  updatedAt: timestamp
  
  // 模块
  setting: ProjectSetting
  characters: Character[]
  outline: Outline
  episodes: Episode[]
  
  // 元数据
  progress: number  // 0-100
  currentStep: string
}

// 角色
Character {
  id: string
  name: string
  role: string  // "主角" | "配角" | "反派"
  personality: string
  background: string
  goal: string
  relationships: Relationship[]
  versions: Version[]
}

// 大纲
Outline {
  id: string
  structure: string  // "三幕" | "五幕"
  acts: Act[]
  versions: Version[]
}

// 剧本（集）
Episode {
  id: string
  number: number
  title: string
  summary: string  // 梗概
  scenes: Scene[]
  versions: Version[]
}

// 场景
Scene {
  id: string
  number: number
  setting: string  // "日/内/咖啡厅"
  description: string
  dialogues: Dialogue[]
}

// 版本
Version {
  id: string
  content: any
  timestamp: timestamp
  description: string
}
```

## 8. 风险与限制

### 8.1 已知限制
- 不直接调用AI API，无法自动生成内容
- 依赖用户手动复制粘贴
- AI输出质量不可控（取决于用户使用的AI平台）

### 8.2 潜在风险
- 不同AI平台输出格式差异
- 用户可能不理解"上下文自包含"概念
- 长剧本管理的性能问题

### 8.3 缓解措施
- 提供详细的使用教程和示例
- 针对主流AI平台提供特定优化
- 实现数据分页和懒加载

## 10. RealWeb集成说明 ✨ 新增

1. 提交代码到 RealWeb 仓库
