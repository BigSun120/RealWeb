# 分集检查功能 - 需求概述

## 📋 文档说明

本文档定义**剧本医生 - 分集检查（Episodes Check）**功能的完整需求，包括功能定位、用户场景、技术方案和实现路径。

---

## 🎯 功能定位

### 核心价值

**分集检查**是剧本医生三大诊断阶段中的第二阶段，用于对**已完成的分集剧本**进行质量诊断和优化建议。

### 与其他阶段的关系

```
创作流程：
1. 前期检查 (preparation) 
   → 世界观、角色、大纲基础设定
   ↓
2. 分集检查 (episodes) ⭐ 本需求
   → 已完成剧集的内容质量
   ↓
3. 整体检查 (overall)
   → 全局一致性和节奏把控
```

---

## 🚫 明确的功能边界

### ✅ 本功能负责

1. **诊断已完成的分集剧本质量**
   - 剧情逻辑性
   - 对白质量
   - 人物塑造
   - 节奏把控
   - 悬念设置

2. **生成问题清单**
   - 定位到具体集数
   - 提供详细问题描述
   - 标注严重程度

3. **提供优化方案**
   - AI生成修改建议
   - 显示修改前后对比
   - 支持一键应用方案

### ❌ 本功能不负责

1. **分集剧本的创作**
   - 这是分集剧本模块的职责
   - 已有完整包下载功能
   - 已有提示词生成功能

2. **分集剧本的编辑**
   - 诊断后需要修改 → 跳转到分集剧本编辑
   - 不在剧本医生内实现编辑器

3. **新建分集**
   - 不在诊断流程中创建剧集

## 👥 用户场景

### 场景1：单集质量检查

**用户故事**：
> 作为编剧，我刚完成第5集的创作，想知道这一集是否存在质量问题。

**操作流程**：
1. 用户进入【剧本医生】→【分集检查】
2. 在已完成剧集列表中选择"第5集"
3. 点击"诊断本集"按钮
4. 系统生成诊断提示词 + 下载完整包链接
5. 用户去外部AI（ChatGPT/Claude）提交
6. 用户将AI回答粘贴回系统
7. 系统解析问题列表并展示
8. 用户查看问题、生成修改方案、应用修改

**关键点**：
- ✅ 完整包已在全局工具中可下载
- ✅ 使用外部AI模式（不直接调用内部API）
- ✅ 支持导入AI回答并解析

---

### 场景2：批量诊断

**用户故事**：
> 作为编剧，我已经完成了前10集，想统一做一次质量检查。

**操作流程**：
1. 用户进入【剧本医生】→【分集检查】
2. 勾选要检查的剧集（如第1-10集）
3. 点击"批量诊断"
4. 系统为每一集生成独立的诊断提示词
5. 用户逐一提交外部AI（或使用批处理模式）
6. 用户逐一导入AI回答
7. 系统汇总所有问题并分类展示

**关键点**：
- ✅ 支持多选剧集
- ✅ 生成独立的提示词文件
- ✅ 支持批量导入

---

### 场景3：问题修复流程

**用户故事**：
> AI发现第5集的对白过于生硬，我需要查看具体问题并获取修改建议。

**操作流程**：
1. 用户在问题列表中看到"第5集-对白生硬"问题
2. 点击"生成解决方案"
3. 系统生成方案提示词（包含完整上下文）
4. 用户提交外部AI
5. 用户导入AI建议
6. 查看【原剧本】vs【AI建议剧本】对比
7. 点击"应用修改"
8. 系统更新第5集剧本内容
9. 标记问题为"已解决"

**关键点**：
- ✅ 解决方案也使用外部AI模式
- ✅ 需要包含完整上下文（项目设定+前几集内容）
- ✅ 更新后自动刷新分集剧本数据

---

## 🔧 技术方案概述

### 方案选择：外部AI模式

**决策理由**：
1. **Token成本控制** - 分集检查需要大量上下文（完整包可能5000-15000 tokens）
2. **避免上下文丢失** - 完整包作为附件形式提供，不会被截断
3. **用户灵活性** - 用户可选择不同的外部AI（GPT-4/Claude等）
4. **现有基础设施** - 完整包下载功能已存在

**工作流程**：
```
剧本医生 → 生成提示词 
         → 提示用户下载完整包（全局工具）
         → 用户去外部AI
         → 用户复制AI回答
         → 粘贴到系统
         → 解析并展示问题
```

---

### 核心组件复用

| 组件 | 现有功能 | 本需求复用 |
|------|----------|-----------|
| **完整包生成** | 分集剧本已有 | ✅ 直接复用 |
| **提示词生成** | 前期检查已有 | ✅ 参考模式 |
| **问题解析** | AIService.parseDiagnosisResult() | ✅ 直接复用 |
| **问题管理** | aiIssues[] | ✅ 扩展结构 |
| **解决方案生成** | generateSolution() | ✅ 改造适配 |
| **内容更新** | UpdateStrategyFactory | ✅ 使用EpisodeUpdateStrategy |

## 📊 数据模型扩展

### Issue对象扩展

```javascript
{
  id: string,
  title: string,
  description: string,
  severity: 'critical' | 'medium' | 'low',
  location: {
    module: 'episodes',          // ✅ 固定为episodes
    field: '第5集',               // ✅ 使用"第X集"格式
    episodeNumber: 5,            // ✅ 集数编号
    subField?: string            // ⭐ 新增：子字段（如'对白'、'场景'）
  },
  context: {                     // ⭐ 新增：上下文信息
    episodeTitle: '契约的开始',
    episodeStatus: 'completed',
    wordCount: 1200
  },
  status: 'pending' | 'solution_ready' | 'solved' | 'ignored',
  solution?: {
    suggestedContent: string | object,
    explanation: string,
    generatedAt: string
  },
  generating: boolean
}
```

**关键变更**：
- `location.field` 使用 `"第X集"` 格式（与大纲"第X幕"保持一致）
- 新增 `episodeNumber` 便于快速定位
- 新增 `subField` 支持更细粒度定位（如某集的对白、场景描述）
- 新增 `context` 提供额外上下文信息

## 📝 实现优先级

### Phase 1 - MVP（核心功能）

✅ **必须实现**：
1. 剧集选择器（单选/多选）
2. 生成分集诊断提示词
3. 外部AI工作流引导（3步向导）
4. 导入并解析AI回答
5. 问题列表展示（按集数分组）
6. 生成解决方案（外部AI模式）
7. 应用解决方案到分集内容

**预计工作量**：3-4天

---

### Phase 2 - 优化

✅ **建议实现**：
1. 批量诊断优化（并行导入多个AI回答）
2. 问题统计图表（各集问题分布）
3. 诊断历史记录
4. 问题修复进度追踪

**预计工作量**：2-3天

---

### Phase 3 - 高级功能

⭐ **可选实现**：
1. 自动化检查（定时诊断新完成的剧集）
2. 质量评分系统（为每集打分）
3. 导出诊断报告（PDF/Markdown）
4. AI建议的版本对比（多次生成对比）

**预计工作量**：3-5天
