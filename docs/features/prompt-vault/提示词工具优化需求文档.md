## 🔹 Phase 1: 使用记录追踪

### 功能描述
记录每次提示词的使用情况，包括使用时间、输入参数、效果反馈等。

### 后端实现

#### 1.1 数据模型设计
**文件**: `backend/src/models/PromptUsageLog.js`

```javascript
// 字段列表：
- promptId: 提示词ID (必填)
- userId: 用户ID (必填)
- usedAt: 使用时间 (自动)
- variables: 使用的变量值 (JSON)
- renderedContent: 渲染后的内容
- feedback: 用户反馈 (可选)
  - rating: 评分 (1-5星)
  - comment: 评论内容
  - isEffective: 是否有效
- performance: 性能数据 (可选)
  - responseTime: 响应时间(ms)
  - tokenCount: Token 数量
```

#### 1.2 API 接口设计
**文件**: `backend/src/controllers/promptUsageController.js`

**接口列表**:
1. `POST /api/prompts/:id/usage` - 记录使用
2. `GET /api/prompts/:id/usage` - 获取使用记录列表
3. `PATCH /api/prompts/usage/:logId/feedback` - 更新反馈

**路由文件**: `backend/src/routes/prompt-usage.js`

### 前端实现

#### 1.3 使用记录功能集成
**修改文件**: `frontend/src/views/tools/productivity/components/PromptUsage.vue`

**新增功能**:
- 在提示词使用后自动记录使用日志
- 用户可以选择性提交反馈（评分、评论）

## 🔹 Phase 3: 版本历史管理

### 功能描述
自动记录提示词的每次修改，支持查看历史版本和版本对比。

### 后端实现

#### 3.1 版本历史存储策略
**方案选择**: 在 PromptTemplate 模型中增加 `versions` 字段（数组）

**修改文件**: `backend/src/models/PromptTemplate.js`

**字段结构**:
```javascript
versions: [{
  versionNumber: Number,      // 版本号 (自增)
  title: String,              // 标题快照
  content: String,            // 内容快照
  description: String,        // 描述快照
  variables: Array,           // 变量快照
  updatedBy: ObjectId,        // 修改人
  updatedAt: Date,            // 修改时间
  changeLog: String           // 变更说明 (可选)
}]
```

#### 3.2 自动版本记录
**修改文件**: `backend/src/controllers/promptController.js`

**逻辑**: 在更新提示词时 (PUT 请求)，自动创建版本快照

#### 3.3 API 接口设计
**新增接口**:
1. `GET /api/prompts/:id/versions` - 获取版本历史列表
2. `GET /api/prompts/:id/versions/:versionNumber` - 获取特定版本详情
3. `POST /api/prompts/:id/versions/:versionNumber/restore` - 恢复到指定版本

### 前端实现

#### 3.4 版本历史组件
**新建文件**: `frontend/src/views/tools/productivity/components/PromptVersionHistory.vue`

**展示内容**:
- 版本时间线（倒序显示）
- 每个版本的标题、修改人、修改时间
- 点击版本查看详情
- 版本对比功能（两个版本的 diff）
- 恢复到指定版本（需确认）

#### 3.5 版本历史入口
**修改文件**: `frontend/src/views/tools/productivity/PromptVaultWorking.vue`

**菜单项**: "版本历史"

## 🔹 Phase 4: 评论系统

### 功能描述
允许用户对提示词添加评论、回复评论、点赞评论，支持问题反馈。

### 后端实现

#### 4.1 评论数据模型
**新建文件**: `backend/src/models/PromptComment.js`

**字段列表**:
```javascript
- promptId: 提示词ID (必填)
- userId: 评论用户ID (必填)
- content: 评论内容 (必填)
- parentId: 父评论ID (用于回复)
- createdAt: 创建时间
- updatedAt: 更新时间
- likes: 点赞用户ID数组
- isResolved: 是否已解决 (用于问题反馈)
```

#### 4.2 API 接口设计
**新建文件**: `backend/src/controllers/promptCommentController.js`

**接口列表**:
1. `GET /api/prompts/:id/comments` - 获取评论列表（支持分页）
2. `POST /api/prompts/:id/comments` - 添加评论
3. `POST /api/prompts/comments/:commentId/reply` - 回复评论
4. `PATCH /api/prompts/comments/:commentId/like` - 点赞/取消点赞
5. `PATCH /api/prompts/comments/:commentId/resolve` - 标记为已解决
6. `DELETE /api/prompts/comments/:commentId` - 删除评论（仅作者和管理员）

**路由文件**: `backend/src/routes/prompt-comments.js`

### 前端实现

#### 4.3 评论组件开发
**新建文件**: `frontend/src/views/tools/productivity/components/PromptComments.vue`

**功能特性**:
- 评论列表（树形结构，显示回复）

- 点赞按钮

#### 4.4 评论入口添加

## 🔹 Phase 5: 批量导入导出

### 功能描述
支持批量导入导出提示词，方便数据备份和迁移。支持 JSON 和 CSV 格式。

### 后端实现

#### 5.1 导入导出工具
**新建文件**: `backend/src/utils/promptImportExport.js`

**功能函数**:
- `exportToJSON(promptIds)` - 导出为 JSON
- `exportToCSV(promptIds)` - 导出为 CSV
- `importFromJSON(jsonData, userId)` - 从 JSON 导入
- `importFromCSV(csvData, userId)` - 从 CSV 导入
- `validateImportData(data)` - 数据验证
- `detectDuplicates(data)` - 重复检测

#### 5.2 API 接口设计
**新增接口**:
1. `POST /api/prompts/export` - 导出提示词
   - Body: `{ promptIds: [], format: 'json/csv' }`
   - 返回: 文件流
2. `POST /api/prompts/import` - 导入提示词
   - Content-Type: multipart/form-data
   - Body: 文件上传
3. `POST /api/prompts/import/validate` - 验证导入文件
   - 返回: 验证结果和问题列表

### 前端实现

#### 5.3 导入导出组件
**新建文件**: `frontend/src/views/tools/productivity/components/PromptImportExport.vue`

**功能模块**:

**导出功能**:
- 选择导出格式（JSON/CSV）
- 选择导出范围（全部/选中/当前文件夹）
- 下载按钮

**导入功能**:
- 文件上传区域（拖拽/点击上传）
- 支持的格式提示
- 导入预览（显示将导入多少条）
- 重复处理策略选择（跳过/覆盖/创建新的）
- 导入进度显示

**修改文件**: `frontend/src/views/tools/productivity/PromptVaultWorking.vue`

**位置**: 顶部工具栏

## 📐 技术规范

### 代码规范
1. **前端**: 遵循 Vue 3 Composition API 风格
2. **后端**: 遵循 Express.js 最佳实践
3. **命名**: 驼峰命名法，变量名要有意义
4. **注释**: 关键逻辑必须添加注释

### 错误处理
1. 后端所有接口必须有统一的错误处理
2. 前端需要友好的错误提示信息
3. 网络错误、超时要有重试机制

### 性能要求
1. 列表接口响应时间 < 300ms
2. 统计接口响应时间 < 500ms
3. 导入导出大文件时要有进度显示
4. 前端组件懒加载，减少首屏加载时间

### 安全要求
1. 所有写操作需要身份验证
2. 用户只能操作自己的数据（除管理员）
3. 文件上传需要类型和大小限制
4. 防止 XSS 和 SQL 注入
