# 提示词模板 - Bug修复说明

## 修复日期
2025-10-15

## 问题描述

### 症状
用户没有修改默认模板，直接切换为【自定义模板】后点击预览，出现以下问题内容：

```
# 第1集剧本创作任务

注意：细致阅读并理解附件内容！

## 项目信息
- 剧本名称：测试
- 剧本类型：复仇爽剧
- 总集数：60集
- 当前集数：第1集
- 集名：初次相遇
{{/if}}    ← ⚠️ 未处理的模板标记
```

### 根本原因

#### 问题1: watch监听器过度覆盖 (PromptTemplateEditor.vue)

**位置**: 第445-456行

**问题链条**:
1. 用户切换 `useCustom` 从 `false` 到 `true`
2. `handleUseCustomChange` 正确地设置了 `localTemplate.value.customTemplate = DEFAULT_PROMPT_TEMPLATE`
3. 但是组件 emit 更新父组件后，父组件再次传回 `modelValue`
4. watch 监听器被触发，执行：
   ```javascript
   customTemplate: newVal.customTemplate ?? DEFAULT_PROMPT_TEMPLATE
   ```
5. 如果父组件传回的 `newVal.customTemplate` 仍然是 `null`，`??` 运算符不会生效
6. 结果：**本地刚设置的 customTemplate 被 null 覆盖**

#### 问题2: 嵌套条件块处理不完整 (promptTemplates.js)

**位置**: 第138-180行

**问题结构**:
```javascript
{{#if previousEpisode}}
  ## 上集回顾
  {{#if previousEpisode.title}}
    - 标题：{{previousEpisode.title}}
  {{/if}}
  {{#if previousEpisode.summary}}
    - 内容：{{previousEpisode.summary}}
  {{/if}}
{{/if}}
```

**问题**:
- 旧的正则表达式只能匹配**最内层不包含嵌套的条件块**
- 对于三层嵌套结构，处理顺序不当可能导致某些 `{{/if}}` 残留

## 修复方案

### 修复1: 优化 watch 监听器逻辑

**文件**: `PromptTemplateEditor.vue` 第446-465行

**修复前**:
```javascript
watch(() => props.modelValue, (newVal) => {
  if (newVal && JSON.stringify(newVal) !== JSON.stringify(localTemplate.value)) {
    localTemplate.value = {
      useCustom: newVal.useCustom ?? false,
      customTemplate: newVal.customTemplate ?? DEFAULT_PROMPT_TEMPLATE,  // ❌ 问题
      lastModified: newVal.lastModified ?? null
    };
    originalTemplate.value = JSON.parse(JSON.stringify(localTemplate.value));
  }
}, { deep: true });
```

**修复后**:
```javascript
watch(() => props.modelValue, (newVal) => {
  if (newVal && JSON.stringify(newVal) !== JSON.stringify(localTemplate.value)) {
    // 修复：避免覆盖本地已设置的 customTemplate
    // 只有在以下情况才更新 customTemplate:
    // 1. 本地没有 customTemplate 且父组件传来了新值
    // 2. 父组件传来的值与本地不同且不是 null
    const shouldUpdateCustomTemplate = 
      (!localTemplate.value.customTemplate && newVal.customTemplate) ||
      (newVal.customTemplate && newVal.customTemplate !== localTemplate.value.customTemplate);
    
    localTemplate.value = {
      useCustom: newVal.useCustom ?? localTemplate.value.useCustom,
      customTemplate: shouldUpdateCustomTemplate 
        ? newVal.customTemplate 
        : localTemplate.value.customTemplate,  // ✅ 保留本地值
      lastModified: newVal.lastModified ?? localTemplate.value.lastModified
    };
    originalTemplate.value = JSON.parse(JSON.stringify(localTemplate.value));
  }
}, { deep: true });
```

**修复效果**:
- ✅ 本地设置的 `customTemplate` 不会被父组件的 `null` 覆盖
- ✅ 只在真正需要同步时才更新
- ✅ 保留用户在切换过程中的操作

### 修复2: 重写条件块处理算法

**文件**: `promptTemplates.js` 第138-253行

**修复前**:
```javascript
function processConditionals(text) {
  let hasMatch = true;
  
  while (hasMatch) {
    hasMatch = false;
    
    // 使用正则从内到外处理
    const pattern = /{{#if\s+([\w.]+)}}((?:(?!{{#if|{{\/if}}).)*){{\\/if}}/s;
    
    text = text.replace(pattern, (match, condition, content) => {
      // ... 处理逻辑
    });
  }
  
  return text;
}
```

**问题**: 正则表达式在处理三层嵌套时可能留下未匹配的 `{{/if}}`

**修复后**:
```javascript
function processConditionals(text) {
  let maxIterations = 50; // 防止无限循环
  let iteration = 0;
  
  while (iteration < maxIterations) {
    iteration++;
    
    // 使用栈来匹配配对的 if/endif，处理任意层级的嵌套
    let result = '';
    let i = 0;
    let modified = false;
    
    while (i < text.length) {
      // 1. 查找 {{#if
      const ifStart = text.indexOf('{{#if', i);
      if (ifStart === -1) {
        result += text.substring(i);
        break;
      }
      
      // 2. 提取条件名称
      const conditionStart = ifStart + 5;
      const conditionEnd = text.indexOf('}}', conditionStart);
      const condition = text.substring(conditionStart, conditionEnd).trim();
      
      // 3. 使用深度计数器查找匹配的 {{/if}}
      let depth = 1;
      let pos = conditionEnd + 2;
      let endifPos = -1;
      
      while (pos < text.length && depth > 0) {
        const nextIf = text.indexOf('{{#if', pos);
        const nextEndif = text.indexOf('{{/if}}', pos);
        
        if (nextIf !== -1 && nextIf < nextEndif) {
          depth++;  // 遇到嵌套的 if
          pos = nextIf + 5;
        } else {
          depth--;  // 遇到 endif
          if (depth === 0) {
            endifPos = nextEndif;
          }
          pos = nextEndif + 7;
        }
      }
      
      // 4. 提取内容并评估条件
      const content = text.substring(conditionEnd + 2, endifPos);
      let value = evaluateCondition(condition, vars);
      
      if (value && value !== '' && value !== 0) {
        result += content;  // 条件为真，保留内容
        modified = true;
      }
      // 条件为假，跳过整个块
      
      i = endifPos + 7;
    }
    
    text = result;
    
    if (!modified) {
      break;  // 没有更多条件块需要处理
    }
  }
  
  return text;
}
```

**修复效果**:
- ✅ 使用**深度计数器**精确匹配嵌套的 `{{#if}}` 和 `{{/if}}`
- ✅ 支持任意层级的嵌套（不仅限于三层）
- ✅ 一次性完整移除条件块，不会留下残留标记
- ✅ 防止无限循环（最多迭代50次）

## 关键改进点

### 1. 数据流控制
- **旧逻辑**: 父组件→子组件的单向强制覆盖
- **新逻辑**: 智能判断，本地优先，按需同步

### 2. 算法优化
- **旧算法**: 正则表达式匹配（边界情况处理不完善）
- **新算法**: 深度计数器 + 栈模拟（精确匹配任意嵌套）

### 3. 容错性
- **旧代码**: 异常情况可能导致死循环或残留标记
- **新代码**: 最大迭代次数限制 + 格式错误保留原样

## 追加修复: 插入变量时编辑器滚动问题

### 问题描述
**症状**: 在【可用变量】中点击任意变量后，变量正确添加到光标位置，但【模板编辑器】会自动滚动到最底端。

**原因**: 
- 在 `insertVariable` 函数中，调用 `textarea.focus()` 和 `textarea.setSelectionRange()` 后
- 浏览器会自动将光标位置滚动到可视区域
- 但没有保持原有的 `scrollTop` 和 `scrollLeft`，导致意外滚动

### 修复方案

**文件**: `PromptTemplateEditor.vue` 第300-331行

**修复前**:
```javascript
const insertVariable = (varName) => {
  // ...
  const textarea = document.querySelector('.template-textarea textarea');
  if (textarea) {
    const start = textarea.selectionStart;
    const end = textarea.selectionEnd;
    // ... 插入变量
    
    setTimeout(() => {
      textarea.focus();
      textarea.setSelectionRange(newPos, newPos);
      // ⚠️ 没有恢复滚动位置
    }, 10);
  }
};
```

**修复后**:
```javascript
const insertVariable = (varName) => {
  // ...
  const textarea = document.querySelector('.template-textarea textarea');
  if (textarea) {
    // ✅ 保存当前滚动位置
    const scrollTop = textarea.scrollTop;
    const scrollLeft = textarea.scrollLeft;
    
    const start = textarea.selectionStart;
    const end = textarea.selectionEnd;
    // ... 插入变量
    
    setTimeout(() => {
      textarea.focus();
      textarea.setSelectionRange(newPos, newPos);
      
      // ✅ 恢复滚动位置，防止自动滚动到底部
      textarea.scrollTop = scrollTop;
      textarea.scrollLeft = scrollLeft;
    }, 10);
  }
};
```

**修复效果**:
- ✅ 插入变量后编辑器保持在原位置
- ✅ 不会意外滚动到底部或顶部
- ✅ 用户体验流畅，符合预期

**测试场景**:
1. 开启自定义模板
2. 滚动到模板中间位置
3. 将光标放置在任意位置
4. 点击右侧变量面板中的任意变量
5. **预期结果**: 变量插入光标位置，编辑器保持在原滚动位置
