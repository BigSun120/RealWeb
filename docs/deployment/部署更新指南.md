# ✅ 标准部署（Git 最通用做法）

下述流程采用“本地提交并推送到 GitHub，服务器通过 Git 拉取”的方式，是最通用、最正规、可追踪回滚的部署方式。每一步都标明“在本地执行/在服务器执行”。

- 服务器地址: 74.48.194.227
- 项目目录: /root/RealWeb
- 仓库地址: git@github.com:BigSun120/RealWeb.git 或 https://github.com/BigSun120/RealWeb.git
- 主分支: master
- 后端进程: PM2 进程名 website-backend（端口 8000 由 Nginx 反代）
- 前端静态资源目录: /var/www/html/
- 邮件服务: Postfix(端口 25) + Inbucket(端口 2500/9000)

## 1) 在本地执行：提交并推送

```bash

# 1. 拉取最新代码（避免冲突）
git pull origin master

# 2. 提交本地更改
git add .
git commit -m "ai10.16-提示词完善04"

# 3. 推送到远程
git push origin master

# 启动服务（而不是重启，因为进程可能不存在）
pm2 start ecosystem.config.js --env production

pm2 restart website-backend

cd frontend
npm run build
scp -r dist/* root@74.48.194.227:/var/www/html/


pm2 logs website-backend --lines 40

# 重启 Inbucket
docker restart inbucket-temp

```

## 2) 在服务器执行：拉取并部署

```bash
# 1. SSH 登录服务器（在本地终端执行）
ssh root@74.48.194.227

# 2. 切到项目目录（在服务器执行）
cd ~/RealWeb

# 3. 拉取最新代码（在服务器执行）
# 常用且安全：
c
# 若服务器上曾经手动改过文件导致冲突，可以使用：
# git fetch origin && git reset --hard origin/master

# 4. 安装后端依赖（前端不在服务器构建）
cd backend && npm install && cd ..

# 5. 重启后端服务（在服务器执行）docker restart inbucket-temp
pm2 restart website-backend

# 提示：前端请按下文“5) 本地构建并上传部署（通用且稳定）”在本地构建后，用 scp/rsync 上传至 /var/www/html
```

## 4) 环境变量与进程（推荐一次性配置，非每次必做）

- 后端依赖的环境变量（如 PORT、MONGODB_URI、FRONTEND_URL、UPLOAD_PATH、JWT_SECRET）建议通过 PM2 生态文件统一管理，避免重启丢失。
- 示例（仅说明，实际文件名：ecosystem.config.js）：

```js
module.exports = {
  apps: [
    {
      name: 'website-backend',
      script: 'backend/app.js',
      instances: 1,
      exec_mode: 'fork',
      env_production: {
        NODE_ENV: 'production',
        PORT: 8000,
        MONGODB_URI:
          'mongodb://admin:your_strong_password_here@127.0.0.1:27017/personal_website_prod?authSource=admin',
        FRONTEND_URL: 'http://godaug.fun',
        UPLOAD_PATH: '/var/www/uploads'
        // JWT_SECRET: "请使用安全的随机密钥"
      }
    }
  ]
};
```

应用方式（在服务器执行）：

```bash
cd ~/RealWeb
pm2 delete website-backend || true
pm2 start ecosystem.config.js --env production
pm2 save
pm2 startup  # 按提示执行一条命令以开机自启
```

## 6) 服务器服务重启与排障速查

### 后端（PM2 管理的 Node 服务）

```bash
# 重启后端
pm2 restart website-backend

# 查看状态与最近日志
pm2 status
pm2 logs website-backend --lines 20

# 使用 PM2 生态文件重新拉起（如修改了 ecosystem.config.js 或环境变量）
cd ~/RealWeb
pm2 delete website-backend || true
pm2 start ecosystem.config.js --env production
pm2 save
```

### 前端（Nginx 提供静态文件）

- 仅替换 /var/www/html 下的文件时，无需重启任何服务
- 仅在 Nginx 配置变更时 reload（不是 restart）

```bash
# 语法检查 & 热重载
nginx -t && systemctl reload nginx

# 如需完整重启（一般不需要）
systemctl restart nginx

# 查看 Nginx 日志（排查 404/配置问题）
tail -n 100 /var/log/nginx/error.log
```
