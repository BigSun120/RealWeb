# 临时邮箱权限控制需求文档

## 📋 **需求概述**

### **当前状态**
- 临时邮箱功能完全公开，任何人都可以免费使用
- 无需登录即可生成邮箱、查看邮件等操作
- 只有删除邮件需要管理员权限

### **目标状态**
- 必须登录才能使用临时邮箱功能
- 需要管理员配置的激活验证码才能开通权限
- 管理员可以控制和管理用户的使用权限

## 🎯 **核心功能需求**

### **1. 权限控制层级**
```
基础权限：用户必须登录
↓
激活权限：需要输入管理员配置的激活验证码
↓
使用权限：激活后可以正常使用临时邮箱功能
↓
管理权限：管理员可以管理激活码和用户权限
```

### **2. 激活验证码管理**
- **管理员配置**：在后台设置激活验证码
- **码值管理**：支持生成、修改、禁用验证码
- **有效期控制**：可设置验证码有效期
- **使用统计**：记录验证码使用次数和用户
- **批量管理**：支持批量生成和管理验证码

### **3. 用户激活流程**
- **登录检查**：访问临时邮箱页面时检查登录状态
- **激活码输入**：首次使用需要输入激活验证码
- **权限授予**：验证成功后授予临时邮箱使用权限
- **状态记录**：记录用户的激活状态和时间

### **4. 权限持久化**
- **用户标记**：在用户模型中添加临时邮箱权限字段
- **权限期限**：可设置权限有效期（可选功能）
- **权限撤销**：管理员可以撤销用户权限
- **权限继承**：新注册用户默认无权限

## 🔧 **技术实现方案**

### **1. 数据库设计**

#### **用户模型扩展**
```javascript
User: {
  tempEmailAccess: {
    enabled: Boolean,        // 是否有权限
    activatedAt: Date,      // 激活时间
    activatedBy: String,    // 使用的激活码
    expiresAt: Date,        // 权限过期时间（可选）
    lastUsedAt: Date,       // 最后使用时间
  }
}
```

#### **激活验证码模型**
```javascript
TempEmailActivationCode: {
  code: String,             // 验证码（唯一）
  description: String,      // 描述说明
  isActive: Boolean,        // 是否启用
  maxUses: Number,          // 最大使用次数（-1为无限制）
  currentUses: Number,      // 当前使用次数
  expiresAt: Date,          // 过期时间
  createdBy: ObjectId,      // 创建者（管理员）
  createdAt: Date,
  updatedAt: Date
}
```

#### **使用记录模型**
```javascript
TempEmailUsageLog: {
  userId: ObjectId,         // 用户ID
  action: String,           // 操作类型（activate/generate/view/delete）
  email: String,            // 相关邮箱地址
  activationCode: String,   // 使用的激活码（仅激活操作）
  timestamp: Date,          // 时间戳
  ipAddress: String,        // IP地址
  userAgent: String,        // 用户代理
}
```

### **2. API接口设计**

#### **权限检查接口**
- `GET /api/temp-email/access-status` - 检查用户权限状态
- `POST /api/temp-email/activate` - 激活临时邮箱权限

#### **管理员接口**
- `GET /api/admin/temp-email/codes` - 获取激活码列表
- `POST /api/admin/temp-email/codes` - 创建激活码
- `PUT /api/admin/temp-email/codes/:id` - 更新激活码
- `DELETE /api/admin/temp-email/codes/:id` - 删除激活码
- `GET /api/admin/temp-email/users` - 获取用户权限列表
- `PUT /api/admin/temp-email/users/:id` - 修改用户权限

### **3. 中间件设计**
```javascript
// 临时邮箱权限检查中间件
const requireTempEmailAccess = async (req, res, next) => {
  // 1. 检查登录状态
  if (!req.user) {
    return res.status(401).json({ message: '请先登录' });
  }
  
  // 2. 检查临时邮箱权限
  if (!req.user.tempEmailAccess?.enabled) {
    return res.status(403).json({ 
      message: '需要激活临时邮箱权限',
      needsActivation: true 
    });
  }
  
  // 3. 检查权限是否过期
  if (req.user.tempEmailAccess.expiresAt && 
      new Date() > req.user.tempEmailAccess.expiresAt) {
    return res.status(403).json({ 
      message: '临时邮箱权限已过期',
      needsActivation: true 
    });
  }
  
  next();
};
```

## 🎨 **用户体验设计**

### **1. 用户流程**

#### **未登录用户**
```
访问 /temp-email 
→ 显示登录提示 
→ 重定向到登录页面 
→ 登录成功后返回临时邮箱页面
```

#### **已登录但未激活用户**
```
访问 /temp-email 
→ 显示激活验证码输入界面 
→ 输入激活码 
→ 验证成功 
→ 显示临时邮箱功能界面
```

#### **已激活用户**
```
访问 /temp-email 
→ 直接显示临时邮箱功能界面
```

### **2. 界面设计要点**
- **激活页面**：简洁的验证码输入界面，包含说明文字
- **权限提示**：清晰的权限状态提示和操作指引
- **错误处理**：友好的错误提示和解决方案
- **状态显示**：在页面显示用户的权限状态和有效期

## 📊 **管理后台功能**

### **1. 激活码管理**
- **列表展示**：显示所有激活码及其状态
- **创建功能**：支持单个和批量创建激活码

- **状态控制**：启用/禁用激活码

- **权限撤销**：撤销用户的临时邮箱权限
- **批量操作**：支持批量管理用户权限

### **3. 使用统计**
- **总体统计**：激活用户数、活跃用户数、邮箱生成数等
- **趋势分析**：使用量趋势图表
- **详细日志**：用户操作日志和审计记录

## 📝 **注意事项**

### **1. 安全考虑**
- 激活验证码应该足够复杂，避免被猜测
- 记录所有权限相关操作的审计日志
- 防止激活码被恶意批量使用
- 定期清理过期的激活码和权限

### **2. 用户体验**
- 提供清晰的权限说明和使用指南
- 激活流程应该简单易懂
- 错误提示要友好且具有指导性
- 考虑为老用户提供平滑的迁移方案

### **3. 运维管理**
- 提供便捷的激活码批量生成工具
- 支持权限的批量管理操作
- 定期备份权限相关数据
- 监控功能使用情况和异常行为
