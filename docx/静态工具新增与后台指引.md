# 静态工具新增与后台指引

## 背景
- 工具列表以后台 /tools 接口为唯一真源，前端仅在接口不可用时回退到静态数据。
- 静态工具元数据统一维护在 shared/static-tools.json，前后端共用。
- 后台提供“同步静态工具”功能，一键导入写死的工具，确保数据库与静态定义保持一致。

## 新增流程概览
1. **编辑静态配置**：在 shared/static-tools.json 中登记新工具的默认元数据，并提交代码。
2. **部署后同步**：登录后台管理 → 工具管理页，点击【同步静态工具】，把静态定义写入数据库。
3. **后台调整**：在工具管理列表中修改描述、分类、排序、展示状态等，保存后即影响前端展示。
4. **验证**：刷新 /tools 页面或指定分类，确认新工具与最新配置已生效。

## 步骤详解

### 1. 编写静态工具元数据
- 静态配置位于 shared/static-tools.json，每个对象代表一个工具：

`json
{
  "id": "augment-token-manager",
  "name": "Augment 令牌管理器",
  "description": "管理 Augment Code 访问令牌，支持 OAuth 认证和令牌存储",
  "icon": "🔑",
  "category": "dev",
  "route": "/tools/dev/augment-token-manager",
  "component": "@/views/tools/dev/AugmentTokenManager.vue",
  "tags": ["Augment", "令牌", "OAuth", "认证", "开发"],
  "featured": true,
  "status": "active",
  "difficulty": "medium",
  "estimatedTime": "2-3分钟",
  "requiresAuth": true,
  "requiresAdmin": false,
  "sortOrder": 1
}
`
- id、oute、component 应与前端路由保持一致；category 对应现有分类；equiresAuth、status 等作为默认值，可在后台再调整。

### 2. 同步静态工具
- 部署后进入 /admin/tools/management，点击页头的【同步静态工具】按钮。
- 同步逻辑：
  - **新增**：数据库缺少的 id 会自动创建，填充静态配置并标记 isStatic = true。
  - **更新**：已存在的工具保留手动修改的核心字段，仅补全路由、组件、图标、标签等基础信息，并标记为静态工具。
  - **跳过**：内容完全一致的记录会被跳过。
- 同步结果会提示新增 / 更新 / 跳过的数量，成功后自动刷新列表。

### 3. 后台调整与发布
- 在工具管理列表中对新工具进行分类、描述、排序、展示状态、权限等配置。
- 这些调整实时影响 /tools 接口，也是前端最终展示的数据。
- 如需隐藏某个静态工具，可直接在后台把状态改为 inactive 或 coming-soon，前端列表会自动过滤。

## 回退与兜底
- rontend/src/services/toolsService.js 仍保留静态兜底：当 /tools 接口请求失败时，会直接加载 shared/static-tools.json 中的定义，确保关键工具可见。
- 当接口可用时，仅使用后台返回的数据，不再自动合并静态元数据，避免与后台设置冲突。

## 维护建议
- 新增静态工具时，务必同时完成页面组件、路由注册与静态配置，缺一不可。
- 如需批量脚本化同步，可调用后台 /admin/tools/sync-static 接口（需管理员权限）。
- 后续若扩展更多静态工具，直接在 JSON 中追加条目并同步即可生效。
